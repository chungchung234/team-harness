팀 구성은 하네스 저장소의 `team.json` 한 파일이다. 이 스킬은 사람과 대화해 그 파일의 안을 만들고, **사람이 "승인"이라고 말한 뒤에만** 적는다.

0. **자리 확인.** 현재 폴더에 `team.json`과 `sync.py`가 없으면 "팀 구조는 하네스 저장소에서 정합니다 — 그 폴더를 열어 주세요"라고 한 줄로 말하고 멈춘다.
1. **지금 구성 읽기.** `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/team_plan.py" show`. 처음 정하는 것이면(기본값 그대로) 처음부터 묻고, 바꾸는 것이면 무엇을 바꾸고 싶은지부터 묻는다.
2. **묻는다 — 한 번에 하나씩, 사람 말로.** 표나 파일 이름을 먼저 꺼내지 않는다.
   ① 사람과 역할: 어떤 역할이 있고 역할마다 몇 명인가 (외주·겸직도)
   ② 만드는 것: 서비스·서버가 몇 개인가, 화면은 웹·앱 중 무엇인가, 디자인 시스템이 따로 있나
   ③ 승인: 정책은 누가 최종으로 보나, 서버·화면·AI·배포는 각각 누가 승인하나
   ④ 제품 한 줄: 무엇을 만드는 팀인가 (모든 저장소 지도 첫머리에 실린다 — 원치 않으면 비운다)
   읽기 관계와 문서 종류는 묻지 않고 제안한다. 사람이 바꾸고 싶어 하면 그때 묻는다.
3. **제안을 만든다.** 원칙:
   - **저장소는 승인하는 사람 단위로 나눈다.** 승인하는 사람이 같으면 합친다(나중에 뺄 수 있다고 한 줄 말한다). 승인하는 사람이 다르면 나눈다.
   - **읽기는 기대는 방향으로.** 정책 → 스펙(개발·화면이 기획을 읽는다), API를 주는 쪽 → 쓰는 쪽(화면이 서버를 읽는다). 모든 저장소가 `memo`를 읽는다. 자기 자신은 읽지 않는다.
   - **문서 종류는 역할 기본값에서.** 기획: 정책서·질문·ADR·회의록·조사 / 서버: 스펙·질문·ADR·설계·회의록·조사 / 화면: 스펙·질문·ADR·회의록·조사 / 디자인·운영: 질문·ADR·조사 / 메모: 없음. 종류 목록은 `team.json`의 `doc_types`.
   - **플러그인은 역할에 맞춘다.** 기획 product · 서버 dev · 화면 frontend · 디자인 ui · 운영 infra · 메모 core. 저장소 하나에 플러그인은 하나다 — 서버와 화면이 한 저장소면 frontend를 고른다(dev를 포함한다).
   - **주인은 역할로 적는다.** 공개 저장소에는 사람 이름을 넣지 않는다. 이름은 팀의 비공개 사본에만.
   - `memo` 저장소는 언제나 둔다(사람의 생각을 두는 곳, `raw: true`).
   제안 전체를 `team.json`과 같은 모양으로 하네스 저장소 루트의 `team-proposal.json`에 쓴다(편집 도구로. `team.json`은 아직 고치지 않는다. 이 파일은 git에 올라가지 않는다). 그리고:
   - `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/team_plan.py" check team-proposal.json` — ✗가 있으면 고쳐서 다시.
   - `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/team_plan.py" show --file team-proposal.json` — 이 표를 사람에게 보인다.
   - 바꾸는 것이면 `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/team_plan.py" diff team-proposal.json [--work <팀 저장소 폴더>]` — 바뀌는 점(새 저장소, 없어지는 저장소와 옮겨야 할 문서, 읽기 관계 변화)을 사람 말로 요약한다.
4. **표와 함께 이유를 두세 줄로.** 왜 합쳤는지, 왜 나눴는지, 무엇을 아직 두지 않았는지. 그리고 "바꿀 곳이 있으면 말씀해 주세요. 이대로면 '승인'이라고 해 주세요."
5. **"승인" 전에는 `team.json`을 고치지 않는다.** 고치라는 말을 들으면 제안 파일을 고쳐 3·4를 다시 한다. "승인"은 이 대화에서 사람이 직접 한 말이어야 한다.
6. **승인 뒤:**
   - `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/team_plan.py" apply team-proposal.json`
   - `python3 build.py` (하네스 저장소 루트)
   - 새 저장소 골격: 어디에 만들지 묻고(기본 `../work`) `python3 sync.py new <이름> --into <폴더>`. 이미 있는 저장소는 `python3 sync.py update <폴더들>`.
   - 원격 저장소는 만들지 않는다. "원격 저장소도 만들까요?"라고 묻고, 원하면 실행할 명령(`python3 remote.py create <이름들>`)을 보여 준다.
   - 없어지는 저장소의 문서는 옮기지 않는다. 옮겨야 할 문서 목록을 보이고, 각 저장소 주인이 승인한 뒤 그 저장소에서 옮긴다.
   - 하네스 저장소의 변경(`team.json`, 플러그인 `repos.json`)은 평소처럼 커밋하고 올린다.
7. **보고(사람 말로):** 적은 것 한 줄 · 만든 골격 · 남은 것(원격 저장소, 문서 옮기기, 팀원 첫 설치).
