저장소에 없는 것은 없는 것이다(철학 방침 ①). 그런데 모든 생각을 정책서·스펙으로 쓸 수는 없다. 그래서 **memo 저장소**가 있다 — 양식도 번호도 승인도 없고, 각자 자기 폴더에 적고 바로 올린다. 여기 있는 것은 그 사람의 **생각**이지 팀의 결정이 아니다.

0. **내 폴더의 구조는 그 사람이 정한다.** 먼저 `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/memo.py" tree`로 내 폴더의 구조와 README 첫 줄을 본다. README에 "어디에 무엇을 둔다"가 있거나 비슷한 주제의 파일이 이미 있으면 **그 자리에** 적는다(`--to <상대경로>`). 구조가 없으면 기본(오늘 날짜 파일). 새 폴더를 만들 만하면 사람에게 한 번 묻는다 — 에이전트가 남의 정리 방식을 정하지 않는다.
1. 사람이 적어 달라고 한 문장을 그대로 — 다듬지 않는다, 요약하지 않는다. 사람이 "주제로 묶어 줘"라고 하면 `--topic`(또는 그 사람 구조의 자리에 `--to`), 회고면 `--retro <스프린트>`.
1-b. **업무 생각만.** 개인 사정·건강·남에 대한 평가처럼 보이면 적기 전에 "이건 팀 전원과 모든 에이전트가 읽고 git 이력에 영구히 남습니다 — 그래도 적을까요?"라고 묻는다.
2. `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/memo.py" add "<문장>" [--topic 주제 | --retro 스프린트]` — 내 폴더(`../memo/people/<이름>/오늘.md`)에 시각과 함께 붙이고, `memo: …`로 커밋해 main에 올린다. 이슈 키는 없어도 된다(원자료 저장소).
3. 결과 한 줄을 사람에게 보인다: 어디에 적혔는지. 실패(저장소 없음·이름 모름·push 실패)는 스크립트가 말하는 대로 사람에게 그대로.
4. **하지 않는 것** — 남의 폴더에 쓰지 않는다. 메모를 근거로 스펙·정책을 고치지 않는다. 메모가 사실은 결정·질문·정책 변경이라면 그렇게 말한다: "이건 메모보다 `/core:ask`(질문) / `/core:adr`(결정) / `/core:catchup`(저장소 문서로 올리기)가 맞다" — 그래도 적어 달라면 적는다.
5. 남의 메모를 읽고 싶으면 `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/memo.py" recent --who <이름>` 또는 `../memo/people/<이름>/`을 연다. 인용할 땐 "<이름> 님 메모(날짜)"라고 출처를 말하고, 근거로 쓰지 않는다.
