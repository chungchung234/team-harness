# SPEC-01: 주문 취소 API

> 시연용 예시 스펙입니다. 개발 쪽 에이전트가 티켓 ORD-12와 정책서 product/POL-01을 읽고 쓴 모양입니다. 정책서가 바뀌면 이 문서의 에이전트가 다음 말에 알게 됩니다.

## 원천 정책과 대응

| 정책서 수용 기준 | 이 스펙에서 어떻게 구현되는가 | 테스트 |
|---|---|---|
| product/POL-01 A1 — 결제 후 30분 안 취소 | 취소 요청 시 결제 완료 시각과 지금의 차이가 30분 이하면 주문을 취소 상태로 바꾼다 | 29분 뒤 요청 → 취소됨 / 31분 뒤 → 거절 |
| product/POL-01 A2 — 배송 시작 뒤 불가 | 주문 상태가 배송 시작 이후면 거절하고 사유 코드를 돌려준다 | 배송 시작 주문 → 거절 + 사유 |
| product/POL-01 A3 — 전액 환불 | 취소가 확정되면 결제 수단으로 전액 환불을 요청한다 | 취소 후 환불 요청 금액 = 결제 금액 |
| product/POL-01 A4 — 30분 뒤 버튼 숨김 | 주문 조회 응답에 `cancellable`(취소 가능 여부)과 `cancellableUntil`(기한)을 담는다 — 화면은 frontend가 그린다 | 31분 뒤 조회 → cancellable=false |

## 동작 (Behavior)

- 기준 시각은 결제 완료 시각이다(정책 규칙 1).
- 거절 사유: 기한 지남 / 배송 시작됨.
- 부분 취소는 정책서의 열린 질문이라 만들지 않는다.

## 정책서에 물은 것

| 질문 | 어디에 | 상태 |
|---|---|---|
| 30분의 기준은 주문 시각인가 결제 완료 시각인가 | ORD-12 댓글 | 답함 — 결제 완료 시각 (POL-01 규칙 1에 반영됨) |

## 하지 않는 것

- 부분 취소는 정책서가 정하기 전까지 만들지 않는다.
- 반품·교환은 다루지 않는다.
