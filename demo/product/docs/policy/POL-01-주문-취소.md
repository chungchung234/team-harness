# POL-01: 주문 취소

> 시연용 예시 정책서입니다. 기획자가 Claude에게 "주문 취소 정책 써 줘"라고 말해서 나온 모양을 보여 줍니다. 이 정책서를 백엔드와 프론트의 스펙이 함께 가리킵니다.

## 왜 이 정책이 있는가

사용자가 결제 직후 실수를 바로잡을 수 있어야 하고, 배송이 시작된 뒤의 취소는 물류 비용을 만든다. 둘 사이의 경계를 한 곳에서 정한다.

## 정책

1. 결제 완료 후 30분 안에는 사용자가 직접 주문을 [취소](../glossary.md)할 수 있다. 기준 시각은 결제 완료 시각이다.
2. [배송 시작](../glossary.md) 뒤에는 취소할 수 없다.
3. 취소하면 결제 수단으로 전액 환불한다.
4. [취소 가능 시간](../glossary.md)이 지나면 화면에서 취소 버튼을 숨긴다.

## 수용 기준 (Acceptance)

| # | 상황 (Given/When) | 기대 (Then) |
|---|---|---|
| A1 | 결제 완료 후 30분 안에 사용자가 취소를 요청하면 | 주문이 취소된다 |
| A2 | 배송이 시작된 주문에 취소를 요청하면 | 취소되지 않고 사유가 안내된다 |
| A3 | 주문이 취소되면 | 결제 수단으로 전액 환불이 요청된다 |
| A4 | 결제 완료 후 30분이 지나면 | 주문 화면에 취소 버튼이 보이지 않는다 |

## 하지 않는 것 (Out of scope)

- 반품·교환은 다루지 않는다.
- 부분 환불은 다루지 않는다.

## 열린 질문

- 여러 상품을 한 번에 주문했을 때 일부만 취소할 수 있는가? (다음 기획 회의)
