# memo — 메모 — 사람의 생각·회고 (원자료, 근거 아님)

아직 결정도 문서도 아닌 것을 두는 곳 — 개인 메모, 회의 전 생각, 조사 중 발견, 스프린트 회고. **잠금이 없다**(PR 없이 바로 올린다). 여기 있는 것은 그 사람의 생각이지 팀의 결정이 아니다 — 읽고 인용할 수 있으나 근거로 쓰지 않는다. 근거가 되려면 `/core:catchup`으로 `docs/`에 올린다.

## 규칙 세 줄
사람은 지시하고 승인한다. 쓰는 것은 에이전트다. 자기 저장소에 쓰고, 남의 저장소는 읽고 질문한다.
이 저장소에서는 "자기 자리" = **자기 이름 폴더**다.

## 이 저장소 — 소유: 전원 (각자 자기 폴더) · 하네스 담당이 구조만
- 제공하는 것: 없음 — 제공하는 계약이 없다. 모든 저장소가 읽는다
- `people/<이름>/`  각자의 폴더 — **안의 구조는 각자 자유**(README의 "내 폴더 지도"에 적으면 `/core:note`가 따른다). 기본은 날짜 파일
- `retro/`  스프린트 회고·하네스 회의 — 팀이 함께 쓴다
- 양식·번호·상태 없음. 목차 없음. 검사는 시크릿 스캔만. 커밋 메시지에 이슈 키가 없어도 된다(`memo: …`).
- 남의 폴더에 쓰지 않는다. 남의 메모에 할 말이 있으면 자기 메모에 쓰거나 그 사람에게 말한다.
- 여기 적힌 것은 **생각**이다. 다른 저장소의 에이전트는 이것을 읽고 "홍길동 님이 이렇게 보고 있다"고 말할 수 있지만, 스펙·정책의 **근거로 쓰지 않는다**. 근거가 되려면 `/core:catchup`이나 `/core:ask`로 `docs/`에 올라가야 한다.
- **고정은 맨 위 둘뿐** — `people/<이름>/`(누구의 것인가)·`retro/`(팀 회고). **내 폴더 안의 구조는 각자 자유다.** 폴더를 나누든, 주제 파일을 두든, 날짜 파일만 쓰든 그 사람이 정한다. 구조를 에이전트가 알게 하려면 `people/<이름>/README.md`의 "내 폴더 지도"에 한두 줄 — `/core:note`가 먼저 읽고 따른다. 남의 폴더는 읽기만 하고, 정리해 주지 않는다.
- 적는 가장 쉬운 길은 어느 저장소에서든 **`/core:note "한 줄"`** — 내 폴더의 정한 자리(없으면 오늘 날짜 파일)에 붙이고 바로 올린다. PR 없음.
- **업무 생각만** — 팀 전원·모든 에이전트가 읽고 git 이력에 영구히 남는다. 개인 사정·건강·남에 대한 평가는 적지 않는다.

## 공통 규칙
전 저장소 공통 규칙(맥락·소통·문서·git·검사)은 **core 플러그인이 세션 시작에 컨텍스트에 넣는다** — 원문 `harness/plugins/core/RULES.md`. 이 파일에는 이 저장소의 지도만 둔다.
이 저장소가 쓰는 플러그인은 `.claude/settings.json`의 `enabledPlugins`에 있다. 설치 안 됐다는 안내가 뜨면 `claude plugin install <이름>@team-harness`.
