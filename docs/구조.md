# 구조

이 저장소 하나가 곧 Claude Code 플러그인 마켓플레이스 `team-harness`입니다. 팀 저장소에는 지도와 설정만 두고, 동작은 모두 플러그인에서 옵니다.

## 폴더 지도

```
team-harness/
├─ README.md · PHILOSOPHY.md       처음 읽을 것 · 하네스의 철학
├─ .claude-plugin/marketplace.json 마켓플레이스 "team-harness"
├─ plugins/
│   ├─ core/                       모든 저장소 공통 — 훅·스크립트·공통 스킬·공통 규칙(RULES.md)
│   └─ product/ dev/ frontend/ ui/ infra/   역할별 스킬
├─ repo-template/                  저장소 지도(AGENTS.md)와 양식의 원본
├─ sync.py · build.py · remote.py  하네스 담당용 도구
├─ team.json                       팀 구성 — 저장소·주인(역할)·읽는 저장소·폴더·플러그인
├─ remotes.json                    원격 주소·이슈 트래커 등 연결 값
├─ demo/                           시연 저장소 7개 + 주문 취소 예시, try.py
├─ docs/                           이 문서들
├─ tests/                          회귀 시험
└─ .github/workflows/test.yml      올릴 때마다 시험을 돌린다
```

## 플러그인

| 플러그인 | 누가 쓰나 | 스킬 |
|---|---|---|
| core | 모든 저장소 | init · onboard · note · ask · answer · approve · minutes · adr · status · catchup · team |
| product | 기획 | policy · research |
| dev | 백엔드·AI 서버 | feature · spec · bug · research · review-docs |
| frontend | 프론트 | dev 전부 + api-client |
| ui | 퍼블리셔 | tokens · research · review-docs |
| infra | 운영 | research |

역할 플러그인은 모두 `core`에 기대고, `frontend`는 `dev`에 기댑니다. 사람은 스킬 이름을 몰라도 됩니다. 평소처럼 말하면 Claude가 맞는 스킬을 고릅니다.

## 팀 저장소

역할마다 하나씩, 승인하는 사람 단위로 나눕니다.

| 저장소 | 무엇 | 읽는 저장소 |
|---|---|---|
| product | 정책서·용어집·결정 기록 (기획) | memo |
| backend | 서버 스펙·코드 | product · agent · memo |
| agent | AI 서비스 스펙·코드 | product · backend · memo |
| frontend | 화면 스펙·코드 | product · backend · ui · memo |
| ui | 디자인 토큰·컴포넌트 | product · memo |
| infra | 환경·배포 | backend · agent · frontend · memo |
| memo | 사람마다 자기 폴더, 회고 — 생각을 두는 곳(근거 아님) | — |

남의 저장소는 읽기만 합니다. 각 저장소의 `.claude/settings.json`이 읽을 저장소, 켤 플러그인, 허용·금지 명령을 정하고, `AGENTS.md`가 그 저장소의 지도입니다. 둘 다 `sync.py`가 `team.json`을 읽어 만듭니다.
