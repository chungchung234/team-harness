# 시연

Bitbucket·Jira 없이 내 컴퓨터에서 세 사람이 함께 일하는 모습을 만듭니다. 필요한 것: Claude Code, git, python3.

## 만들기

저장소 폴더를 Claude Code로 열고 "써 보고 싶어"라고 말하면 Claude가 아래를 실행합니다. 직접 해도 됩니다.

```
python3 demo/try.py                 # ~/team-harness-work 에 만든다
python3 demo/try.py --work ~/시연    # 다른 곳에
python3 demo/try.py --no-plugins    # 플러그인 설치는 건너뛴다
```

만들어지는 것:

| 폴더 | 무엇 |
|---|---|
| `_원격/` | 시연 저장소 7개를 올려 둔 가짜 원격 (Bitbucket 대신) |
| `기획자/` | 김기획(예시)이 받은 product + memo |
| `백엔드/` | 이백엔드(예시)가 받은 backend + 읽는 저장소 |
| `프론트/` | 박프론트(예시)가 받은 frontend + 읽는 저장소 |

받는 일은 실제 첫 설치와 같은 `init` 스크립트가 합니다. 플러그인은 이 저장소 폴더를 마켓플레이스로 등록해 설치합니다.

## 예시

- product `POL-01` 주문 취소 — 결제 완료 후 30분 안 취소, 배송 시작 뒤 불가, 전액 환불, 기한 뒤 버튼 숨김. 열린 질문 하나, 티켓 댓글에서 온 개정 하나가 들어 있다.
- backend `SPEC-01` 주문 취소 API, frontend `SPEC-01` 취소 버튼 표시 — 둘 다 `related: [product/POL-01]`
- 용어집 3개, 결정 기록 1줄

## 해 보기

1. 창 세 개를 엽니다(기획자/product, 백엔드/backend, 프론트/frontend). 처음 열 때 '신뢰'를 누릅니다.
2. 기획자 창: "주문 취소 정책에서 취소 가능 시간을 30분에서 1시간으로 바꿔 줘"
3. 백엔드 창과 프론트 창: "지금 내 스펙 상태 어때?"

두 창의 Claude가 바뀐 정책과 영향받는 자기 스펙을 먼저 이야기합니다.

더 해 볼 것:

4. 기획자 창: "'둘 사이의 경계를'을 '그 둘의 경계를'로 다듬어 줘" — 뜻이 같은 작은 결정이라 바로 고쳐집니다. 2의 1시간 변경은 큰 결정이라 '검토 중'과 "회의 확정 필요"로 갔습니다.
5. 백엔드 창: "결제 대행사 취소 API가 배송 준비 중에도 취소를 받네. 정책서엔 없는데." — 정책의 빈틈이라 기획 쪽 질문으로 올라갑니다.
6. 기획자 창: "들어온 질문 있으면 처리해 줘" — 문서로 답할 수 있는 것은 근거를 붙여 대신 답하고, 아닌 것은 기획자에게 고르게 합니다. 다음에 창을 새로 열면 대신 답한 것을 모아 보여 줍니다. 처음부터 다시 하려면 시연 폴더를 지우고 `try.py`를 다시 돌립니다.
